# Kant 0.6.0 (Beta)

**Kant on Mac and iPhone, and anyone can host a relay without opening a single port.**

## New

- **Mac.** Kant for macOS, for Apple Silicon (`Kant-0.6.0-mac-arm64.dmg`) and Intel Macs (`Kant-0.6.0-mac-x64.dmg`), with the same built-in relay as the Linux and Windows apps. It isn't notarized by Apple yet, so the first time you open it macOS says it can't verify the developer: open **System Settings → Privacy & Security** and choose **Open Anyway** (check the file's SHA-256 against `SHA256SUMS.txt` first).
- **iPhone.** Kant for iOS 15 and later, as `Kant-0.6.0.ipa` for sideloading (with AltStore, SideStore or Sideloadly), since it isn't on the App Store yet. Unlock with Face ID or Touch ID, open and save files through the share sheet, and get notifications while Kant is open or for about 30 seconds after you leave it. Notifications while Kant is closed need Apple push, which needs an Apple developer account. With a free Apple ID, sideloaded apps have to be refreshed every 7 days.
- **Host a relay without port forwarding.** Run a relay from any computer at home, even behind a router you can't configure or a mobile connection, through Tailscale, Tailscale Funnel, Cloudflare Tunnel or ngrok. One command sets it up, checks it from the outside and prints the address to share: `scripts/relay-tunnel.sh funnel`. See `RELAY_TUNNELS.md`.
- **Easier relay deployment on a server.** `scripts/deploy-relay.sh` asks what it needs (HTTPS with a domain, or HTTP on a local network), checks that the domain points at the server, gets the certificate, and makes the keys for desktop notifications itself. No Firebase, no push proxy and no key tools are needed to run a relay.

## Fixed

- **Desktop notifications from self-hosted relays.** Relays only accepted Web Push keys in an unusual format, so keys made with the standard tool (the one the instructions pointed to) silently didn't work. Both formats work now, and a relay with bad keys says so when it starts.
- **HTTPS relays without Firebase.** The HTTPS setup refused to start unless Firebase settings were filled in, which only the official relay has. It starts without them now.
- **Certificates for new HTTPS relays.** The setup used a placeholder email that Let's Encrypt rejects, so the certificate could fail. It now asks for your email.
- **Local-network relays set up with `deploy-relay.sh --mode http`** told apps to connect to `0.0.0.0`, which never works. They now use the machine's network address.
- **Typing a Tailscale address** (like `100.101.102.103:3001`) as your relay now connects over `http://`, as other local addresses do.

## Tested before release

Everything 0.5.0 was tested with, plus:

- the iPhone app in the iOS Simulator: onboarding, messages both ways with another Kant user, and Face ID unlock
- the Mac app on Apple Silicon and on Intel (under Rosetta): it starts, its built-in relay answers, and a downloaded copy opens past macOS's security check
- a relay hosted at home through a real Tailscale Funnel: messages, a 1 MB file and the app's screens, all through the tunnel
- relays reached through a single port (as every tunnel works): messages, groups, files, relays restarting and phones switching off and on, on one relay and across two linked relays
- ten minutes of connections held open through an HTTPS proxy without a drop

## After updating

- **Nothing changes for existing relays**: 0.6.0 talks to 0.5.x apps and relays, and your chats, contacts and keys are untouched.
- **Relay operators** who use `docker-compose.https.yml` with the Android push proxy: start it with `--profile push` (`scripts/deploy-kant.sh` does this for you). Without the profile the push proxy is left out, which is what everyone else wants.
